## 测试方法

### Prompt 注入规则层

测试集包含以下显式模式：

- 行首 `system/user/assistant/human/ai/model` 角色伪造；
- 中英文“忽略此前指令”“忘记规则”“新指令”等覆盖请求；
- `---简历/文档/问答内容开始或结束---` 静态分隔符伪造；
- `<data-boundary...>` 边界标签伪造。

同时使用 30 条正常工程文本验证误报，包含“系统设计”“用户角色”“忘记密码”
“instruction tuning”等容易与规则关键词接近的正常表达。

本次修正了 `PromptSanitizer.detectInjectionAttempt` 对分隔符和边界标签伪造不告警的问题，
并确保这些模式触发统一安全日志。

### 结构化 JSON 本地修复

构造 20 条字符串字段内部引号未转义的 JSON，例如反馈文本内包含技术术语引号。
每条样本先验证原始 JSON 无法解析，再执行 `StructuredOutputInvoker` 的本地引号修复，
最后使用 Jackson 重新解析并校验字段值未发生变化。

该结果不覆盖 Markdown 代码块、尾逗号、字段缺失、类型错误或任意 JSON 损坏。
项目默认开启 Spring AI Schema Validation；本次指标直接验证本地修复函数所支持的缺陷类型。

## 本机 HTTP 并发基线

测试接口：`GET /api/resumes`。测试期间 PostgreSQL、Redis、RustFS 通过 Docker
运行，Spring Boot 应用在宿主机以单实例运行。数据库中仅有 1 条简历记录。

| 请求数 | 并发数 | 成功/失败 | 吞吐量 | P50 | P95 | P99 | 最大延迟 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1000 | 10 | 1000/0 | 904.72 req/s | 10.13 ms | 18.41 ms | 25.41 ms | 39.33 ms |
| 1000 | 50 | 1000/0 | 951.74 req/s | 41.84 ms | 126.71 ms | 136.49 ms | 180.04 ms |
| 2000 | 100 | 2000/0 | 1433.01 req/s | 61.94 ms | 94.98 ms | 117.31 ms | 209.93 ms |

Prometheus 在三轮测试后的累计统计为 4092 次成功请求，服务端累计处理时间
160.80 秒，当前窗口最大处理时间 199.85 ms。客户端并发测试存在连接调度、JIT
预热和缓存影响，因此不同并发档位不应被解释为严格线性趋势。

该接口属于轻量读请求，且数据量极小。简历中如需引用，必须写成“本机基准”，不能写成
“系统 QPS 达到 1400”或“支持 100 并发用户”。更有业务价值的下一步是测试异步任务入队延迟、
队列等待时间、完整处理耗时和失败恢复率。

## 下一步功能与量化优先级

1. **异步任务全链路指标（最高优先级）**：在 Redis Stream 生产与消费端记录入队响应、队列等待、处理耗时、重试、成功、失败和积压量。现有消费者具备状态流转与最多重试机制，但缺少统一任务指标和失败消息留存。完成后可量化 P95 入队延迟、P95 处理时长、重试恢复率与任务成功率。
2. **失败任务留存与重放**：解析失败或超过重试上限的消息进入死信流，提供查询和人工重放接口，避免当前确认后丢失失败消息。可用故障注入测试量化 100 个失败任务的留存率和重放恢复率。
3. **RAG 离线评测集**：制作 50～100 条带标准相关文档的固定问题，统计 Recall@5、MRR、无答案拒答准确率，并对比 Query Rewrite、动态 Top-K 开关前后差异。这比只写“用了 pgvector/HNSW”更像 Agent/RAG 项目成果。
4. **LLM 质量、延迟和成本面板**：在现有结构化输出 Micrometer 指标基础上，补充模型、Token、首 Token 延迟、总耗时、重试次数和估算费用；按简历分析、出题、评估等场景聚合。
5. **Agent 工具调用闭环**：如果目标是 Agent 岗，增加可审计的工具调用记录、超时/重试、权限白名单、人工确认节点和任务级状态机，并构建工具选择正确率与任务完成率评测集。
6. **端到端可观测性**：为 HTTP、Redis Stream、数据库和 LLM 调用贯通 traceId，接入 OpenTelemetry；该功能工程价值高，但应排在可直接产出业务指标的前四项之后。

上述比例必须与“测试集大小”和“规则层/缺陷类型”同时出现，不应简化成“Prompt 注入防御率 100%”或“JSON 修复率 100%”。
